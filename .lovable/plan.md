## Add Payroll CRUD for Admin & Accountant

Right now `src/pages/Payroll.tsx` is read-only. Admin/Accountant see all invoices but have no UI to create, edit, or delete them. This plan adds the missing CRUD controls — visible only to admin and accountant.

### 1. Add "New payroll invoice" button (header action)

In `src/pages/Payroll.tsx`, pass an `actions` prop to `PageHeader` when `isManager` is true:
- Button labeled "New payroll invoice" with `Plus` icon
- Opens a Dialog form

### 2. Create / Edit dialog

A single Dialog used for both create and edit, with fields:
- **Staff** — Select dropdown populated from `staff` table (id + full_name)
- **Payroll type** — Select: Daily / Weekly / Monthly / One-time
- **Period start / Period end** — date inputs
- **Issued date** — date input (defaults to today)
- **Due date** — date input
- **Gross amount** — number
- **Deductions** — number (defaults 0)
- **Net amount** — number (auto-calculated as gross − deductions, editable)
- **Status** — Select: Draft / Issued / Paid / Cancelled
- **Notes** — textarea

Validation with `zod` (mirroring the pattern in `src/pages/Staff.tsx`):
- staff_id required, gross_amount ≥ 0, deductions ≥ 0, period_end ≥ period_start, due_date required.

On submit:
- Insert into `payroll_invoices` (invoice_number auto-generated by DB default) with `created_by = auth.uid()`
- On edit, update by `id`
- Toast success, invalidate `["payroll-invoices"]`

### 3. Row actions (Edit / Delete)

Add an "Actions" column (manager view only) with:
- **Edit** button → opens the dialog pre-filled
- **Delete** button → `AlertDialog` confirm → deletes from `payroll_invoices` (CASCADE removes related `payroll_payments`)

### 4. Role gating

- Use `isManager = hasAnyRole(roles, ["admin", "accountant"])` (already in file) to show/hide the New button, Actions column, Edit, and Delete.
- Head/regular/guest staff continue to see their own read-only invoices.
- Students remain blocked at the route/nav level.

### 5. RLS note (no migration needed)

Current `payroll_invoices` policy already allows admin / accountant / head_staff to manage rows. Since the UI restricts CRUD to admin + accountant only, no DB change is required. (If you later want DB-level enforcement matching the UI, we can tighten the policy to drop `head_staff` from the manage policy.)

### Files to change

- `src/pages/Payroll.tsx` — add dialog, form state, create/update/delete mutations, actions column, staff dropdown query.

### Test checklist

- Admin: sees "New payroll invoice" button, can create, edit, delete invoices; Actions column visible.
- Accountant: same as admin.
- Head/Regular/Guest staff: no New button, no Actions column, see only own invoices.
- Student: cannot access `/app/payroll`.
- Net amount auto-updates when gross/deductions change but is overrideable.
- Build passes with no TS errors.
